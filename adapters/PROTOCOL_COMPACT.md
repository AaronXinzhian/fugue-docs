# GEB 文档协议(精简版)

代码与文档必须同步:任一方变了、另一方没跟上,任务就没完成。

**结构**:L1 根目录 `PROJECT_INDEX.md`(定位/目录树/依赖图/根文件表);L2 每个含代码的文件夹 `FOLDER_INDEX.md`(文件清单表:文件|职责|关键导出);L3 每个代码文件顶部注释四行:`[INPUT]` 依赖、`[OUTPUT]` 提供、`[POS]` 定位职责、`[PROTOCOL]` 变更时更新此头部并检查上级索引。生成文件/纯配置/vendored 不加头;无代码的文件夹不建索引。

**改代码后(必做)**:1) 更新所改文件 L3 头;2) 核对所属 FOLDER_INDEX.md(增列删清);3) 结构或依赖变了就更新 PROJECT_INDEX.md;4) 有 `geb_sync.py` 先跑它(机器字段自动重写),再跑 `geb_check.py` 验证;5) 汇报末尾附一行 `GEB 回环:L3 ✓ | L2 ✓ | L1 —`。

**动手前**:先读 L1 → 目标 L2 → 目标 L3,再读代码。发现文档与代码不符,顺手修复并说明。

**初始化**:自底向上,真读代码写 L3 → 汇总 L2 → 汇总 L1;禁止凭文件名编造。

**禁止**:改码不改文档;新文件无 L3 头;删文件留幽灵索引;编造文档;把回环拖到以后。
