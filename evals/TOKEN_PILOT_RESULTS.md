# Token 试点记录

目前没有普遍节省率结论,也没有写入已复核净节省账本。最新一轮(Claude Code,外部仓库 Docutils)里,赋格插件与同样带索引的普通 Claude Code 主指标大致持平、通过率更高,钩子本身没有可检出的额外开销;让模型读索引在这些小任务上多花约两成。历史失败和未运行项保留,不按零处理。

## 2026-10-10 Claude Code 三组对比(外部仓库 Docutils)

紧接 A/A,在同一台 Mac 上用同样的 Claude Code 2.1.296、`claude-sonnet-5-5`(默认推理强度)和订阅令牌,跑 4 个任务 × 6 个块 × 3 组 = 72 次,块内顺序随机;付费前自检 12 项全部通过。三组工作区带同一套索引,提示词完全相同,差别只有:

- `index`:没有插件,没有任何提示;
- `hint`:另加项目 `CLAUDE.md`,只有一句"先读 PROJECT_INDEX.md,再读目标目录 FOLDER_INDEX.md 和文件头定位,然后读代码"(与插件注入的第一句相同);
- `fugue`:没有 `CLAUDE.md`,以插件加载赋格钩子。

**完成情况**:72 次全部正常结束,没有接口或执行器故障。通过隐藏验收与整套回归:`index` 19/24,`hint` 24/24,`fugue` 24/24。试验用时合计约 59 分钟(单次中位数约 46 秒),标价折算约 11.67 美元(`index` 3.57、`hint` 4.14、`fugue` 3.97;订阅登录,不是实际扣费)。总 token 24,745,234,其中未缓存输入加输出 1,868,680。

**主指标**(未缓存输入 + 输出;只用两边都通过的同块配对,区间为对数比的 95% 区间):

| 比较 | 配对 | 后者相对前者 | 95% 区间 | 后者更少 / 更多 | 标价成本(95% 区间) |
|------|------|--------------|----------|-----------------|---------------------|
| `hint` 对 `index`:让模型用索引 | 19 | 多 20.7% | 多 13.9% 至多 28.1% | 1 / 18 | 多 15.7%(多 5.6% 至多 26.8%) |
| `fugue` 对 `hint`:钩子本身 | 24 | 少 8.6% | 多 0.5% 至少 16.9% | 17 / 7 | 少 7.3%(多 4.8% 至少 17.9%) |
| `fugue` 对 `index`:整个插件 | 19 | 多 5.7% | 多 16.5% 至少 4.1% | 7 / 12 | 多 0.5%(多 13.4% 至少 10.9%) |

把失败算作输的符号检验(全部 24 块):`hint` 对 `index` 6 胜 18 负(p = 0.023),`fugue` 对 `hint` 17 胜 7 负(p = 0.064),`fugue` 对 `index` 12 胜 12 负(p = 1.0)。

| 任务 | 通过 index / hint / fugue | 主指标中位数 index / hint / fugue | hint 对 index | fugue 对 hint | fugue 对 index |
|------|---------------------------|-----------------------------------|---------------|---------------|----------------|
| figure-figalign | 5 / 6 / 6 | 28,169 / 34,388 / 28,906 | +17%(5 对) | −8% | −4%(5 对) |
| language-fallback | 6 / 6 / 6 | 17,167 / 21,014 / 16,615 | +19% | −19% | −4% |
| rfc-base-url | 6 / 6 / 6 | 19,828 / 22,994 / 21,086 | +21% | −10% | +8% |
| source-date-epoch | 2 / 6 / 6 | 25,248 / 34,950 / 39,269 | +38%(2 对) | +4% | +65%(2 对) |

- **`index` 组为什么失败更多**:5 次失败都通过了隐藏验收,败在整套回归。4 次是 `source-date-epoch`(6 次里 4 次):和 A/A 那次一样,模型新增的测试没有隔离 `test/docutils.conf` 里的日期格式,按官方方式(`test/` 下运行 `alltests.py`)就失败;1 次是 `figure-figalign`,没有更新 `test_CLI` 期望的帮助文本。L1 写明了"在 `test/` 下运行 `alltests.py`":读过 L1 的 `hint`、`fugue` 分别有 21、23 次这样跑了整套测试,`index` 只有 2 次(另有 10 次只在仓库根目录跑,12 次没跑整套)。5 次失败里 4 次没有在 `test/` 下跑过整套测试。所以通过率的提高主要来自 L1 里这一条项目知识,不是索引的定位功能;按[试点设计](token-pilot.md#claude-code-与-docutils),它算作索引收益的一部分。只写一句"测试在 `test/` 下运行"的 `CLAUDE.md` 能否达到同样效果,本轮没有测。
- **读索引为什么反而多花**:任务改动集中、症状具体,`index` 组靠 `grep` 在首次修改前中位数 4 条命令内就找到位置,从不读索引(0/24)。`hint`、`fugue` 每次都读索引(各 24/24),首次修改前也是 4 条命令,但读的文件更多(中位数 5.5 / 6 / 7.5 个)、工具输出更长(约 9.3k / 12.4k / 13.8k 字符),缓存写入随之增加。索引在这里是 `grep` 之外追加的阅读,没有替代搜索。多出来的部分也不是跑整套测试造成的:`index` 没跑整套测试的 9 对里,`hint` 仍多 16%。
- **钩子**:24 次 `fugue` 会话中 Stop 钩子检查 30 次,拦截 6 次(6 个会话各 1 次,共注入 866 字符),自动写入索引 19 次,提示补语义 9 次,出错 0 次。Codex 首轮里完整流程比仅索引多 44%–82%;这一轮钩子没有带来可检出的额外开销,点估计还比 `hint` 少 8.6%,但区间含 0,原因未隔离。
- **其他**:块内先后位置的主指标中位数 23,105 / 22,891 / 25,322,看不出顺序效应。CLI 权限检查拒绝调用 34 / 33 / 37 次,三组相近。

**结论(只限本设置)**:钩子化之后流程本身不再是开销;在小而集中的任务上,让模型读索引多花约两成主指标,定位没有省下命令;插件整体与同样带索引的普通 Claude Code 主指标和标价成本大致持平,通过率从 19/24 升到 24/24,提升主要来自 L1 里怎样运行测试的一条项目知识。所以仍没有"赋格省 token"的结论;能说的是,在这些任务上它没有多花 token,并且写下的项目知识减少了失败。

**边界**:单一模型、单一仓库、4 个改动集中的小任务,提示词直接描述症状;索引是预先写好的,初始化成本没计;配对只用两边都通过的块,失败另由符号检验计入;标价不是实际扣费;补丁未做独立语义复核;定位数值是离线重算的代理。脱敏数值见 [Claude 三组结果](results/2026-10-10-claude-three-arm-hint-sonnet.json);提示词、补丁、事件流、对话记录和本机路径不公开。

**下一步可选方向**(尚未实现或验证):加一组 `CLAUDE.md` 只写测试怎么跑的对照,把"项目知识"和"导航"分开;换跨模块、需要先理解结构的任务,看索引能否替代 `grep` 式阅读;压缩 L1/L2 首读的篇幅。

## 2026-10-10 Claude Code A/A(外部仓库 Docutils)

在你的 Mac 上用 Claude Code 2.1.296、`claude-sonnet-5-5`(默认推理强度)、订阅令牌,对 Docutils 四个任务各跑 2 个 A/A 块:同一个 `index` 组(有索引、没有插件、没有任何提示)跑两遍。付费试验前的零成本自检 12 项全部通过:沙箱生效、工作区外写入与答案目录读取被拦、Bash 看不到凭据、沙箱里 `python3`/`git` 与整套测试能跑、赋格插件与钩子正常。

- **完成情况**:16 次全部正常结束,15 次通过隐藏验收与整套回归,用时合计约 13 分钟(单次 23–152 秒),标价折算约 2.51 美元(订阅登录,不是实际扣费)。总 token 5,379,173,其中未缓存输入加输出 386,617。
- **唯一失败**:`source-date-epoch` 一次,隐藏验收通过,但模型自己新增的测试在官方方式(`test/` 下运行 `alltests.py`)下失败:它没有隔离 `test/docutils.conf` 里的日期格式。原样保留,不修补。
- **噪声**:7 个合格配对,主指标(未缓存输入 + 输出)对数比标准差 0.357;按正态近似,检出 30%、20%、10% 的差异分别约需 8、21、91 对。total token 的标准差 0.731,噪声大得多,不宜作主要判断依据。块内先后位置的主指标中位数 17,970 / 21,421,8 次一组,看不出系统差异。
- **关键观察:没有提示时模型不用索引。**16 次里只有 1 次读过 `PROJECT_INDEX.md`;模型靠 `grep` 在 2–6 条命令内找到要改的位置(首次修改前读 3–7 个文件、约 6–22k 字符工具输出)。所以原计划的"仅索引 对 赋格"实际比较的是"索引被忽略"和"索引被使用 + 钩子"。下一轮改为三组:`index`(无提示)、`hint`(项目 `CLAUDE.md` 只有插件注入的第一句导航提示)、`fugue`(插件与钩子),分别估计"让模型用索引"的收益和钩子本身的开销。
- **环境摩擦**:CLI 的权限检查拒绝了 21 次调用(20 次 Bash:含变量的命令、macOS 的 `sed -i ''`、复合命令等;1 次写工作区外的文件),集中在少数试验;最慢的一次(50 轮、6 次拒绝)也是主指标最高的一次。各组环境相同,计入噪声。
- **分析器修正**:模型多用内联 Python 改文件,旧的定位分析只在 7 次里找到首次修改;还原变量写入目标、排除被拒调用后为 14 次。重算后的定位数值写在结果文件里。

**边界**:这是噪声估计,不比较不同做法,没有任何节省结论;单一模型与仓库;7 对估出的标准差本身也不稳。脱敏数值见 [Claude A/A 结果](results/2026-10-10-claude-aa-sonnet.json);提示词、补丁、事件流、对话记录和本机路径不公开。

**有效配对**:

**验收失败**:无索引的覆盖率任务通过了隐藏功能验收,原有测试文件也保持不变,但新增 `test_root_filter_applies_to_all_summary_fields` 失败。新增测试存储了未规范化的 macOS `/var` 临时路径,而 root 过滤会规范化为 `/private/var`,导致 fixture 不匹配。保留原始未通过状态,不事后修补试验来提高通过率。

**客户端差异**:初次使用 PATH 中的 CLI `0.144.3`,接口以 HTTP 400 拒绝所选模型,执行器立即停止。随后显式指定 App 内置 CLI `0.162.0-alpha.2`,6 个会话上下文均核实为 `gpt-6.1-sol / xhigh`;未切换模型,未修改全局客户端或登录配置。旧客户端的拒绝调用缺完整遥测,用量保持 `null`,所以包含这次准备失败在内的整体支出仍未知,不能称零消耗。模型可用性依赖客户端和账户,参见 [OpenAI 官方模型说明](https://learn.chatgpt.com/docs/models?surface=app)。

**边界**:每任务各组只有一次,仅完成 2/4 个任务,没有 A/A 噪声估计。源码和技能均冻结在 `fdf481065cf7b0b3668786261e27ffbccdabc95d`,不是当前安装版本的全场景测评。自托管仓库约 20 个代码文件,任务集中于计量模块,各组仍可看到协议文档;初始化成本未计入。补丁做过人工抽查,但未做独立盲审,结果等级仍为自动测试通过配对、独立语义复核待完成。因此不推断其他项目收益,也不记入日常账本的已复核净节省。主指标不是实际费用,缓存命中不等于赋格节省。

**下一步优化方向**:先减少技能与项目文档的重复阅读,再试验按变更范围选择轻量/完整维护流程;保留代码阅读、必要索引更新和验收。检验收益时应换用中等规模外部仓库及冻结的当前技能,先估计 A/A 噪声,再用配对试验复核。这些方向尚未实现或验证,本轮没有改写全局赋格规则。

初次预检的输入为 121,379(含缓存 104,064),输出 1,979;缓存是输入子集,不能重复相加。未缓存输入为 17,315。追加对照经用户另行授权 500,000 token 软上限,但它不保证一侧一定能完成,也不能把超时且缺遥测的用量视为零。两次推理强度不同,不能相互配对。

软 token 上限在每次调用结束后检查,所以初次预检超过设定值后才停止。它不是服务端请求硬限额。试验支出与“开发省下的 token”分开,没有记入已复核节省账本。

### 方法局限与修正

两次调用都是开发中的执行器预检,并非正式效果发布。初次预检尚未固定工作副本 Git 边界和原有测试保护;追加对照已加入这些约束,但仍用了 `--ephemeral`。该模式在超时后没有最终 CLI usage,隔离目录也没有可读的会话日志或会话索引行,无法事后恢复用量。

修正后的执行器保留隔离会话日志,不再使用 `--ephemeral`,可单列已上报的 `partial_usage`。部分用量仍不等于完整用量,未知的在途请求可能已消耗 token,因此遇到不完整计量仍停止。修正逻辑通过合成回归验证,本次没有继续调用模型,不宣称真实超时恢复已经完整验收。

赋格侧尚未运行,所以目前没有证据证明这类任务更省或更费 token。未来继续时须重新运行相同设置的两侧,并保留失败率、完整开销、源码与技能摘要,再做独立质量复核。试点方法见 [token-pilot.md](token-pilot.md)。

### 设计变更(2026-10-08)

以上两次预检使用旧的两组设计:两组都有索引,只比较是否额外启用 skill 流程,而且提示词直接点名文件和函数。这个设计测不到索引本身的定位收益,所以即使跑完也只能回答“流程是否额外费 token”。

执行器已改为三组配对块设计(无索引 / 仅索引 / 完整赋格),默认使用不点名位置的症状式提示词,主指标改为未缓存输入加输出,并新增 A/A 噪声模式和离线定位分析。旧记录中的 `baseline` 对应新设计的 `index` 组;新旧结果不能直接配对。独立复核还发现旧执行器给赋格组安装的是当前工作树里的 skill,其中已包含这四个任务的实现;两次预检都没有运行赋格组,已有数值不受影响,新执行器默认把 skill 冻结在源码提交。该设计更新阶段没有调用模型,无模型的任务校验在 4 个任务 × 2 种工作区上全部通过;后续真实首轮结果见本页上方。方法见 [token-pilot.md](token-pilot.md)。
